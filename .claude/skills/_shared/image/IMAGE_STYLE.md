# 포스트 이미지 스타일

PS 포스트의 도식 정본. **도식은 글보다 그림이 이해를 확실히 돕는 경우에만 넣는다**(후보 기준은 `post-reviewer`의 "도식 후보"). 넣는다면 모든 도식이 한 시리즈로 보이도록 일관된 디자인을 쓰고, 라이트·다크 모드를 둘 다 지원한다. 생성은 같은 폴더의 `diagram.py`(팔레트 토큰·그리기 헬퍼·SVG/GIF 출력)를 쓰고, 도식마다 `draw(c, frame, solid_bg)` 함수를 짠다. 샘플 구현: `assets/img/posts/leetcode-202/make_diagrams.py`(노드·간선·포인터 라벨, 사이클 탐색 GIF), `assets/img/posts/leetcode-73/make_diagrams.py`(격자·상태 줄·범례·캡션이 모두 있는 GIF).

## 원칙

- **흑백이 기본, 구분이 필요하면 색을 더한다.** 먹색 윤곽, 옅은 회색 채움, 흐린 회색(제외·미사용)으로 먼저 구성하고, 그것만으로 독자가 상태를 못 가릴 때 색을 추가한다. 색 개수 상한은 없다.
- **한 역할에 한 색, 모든 도식에서 동일.** 새 역할이 생기면 색을 새로 고르되 아래 표에 등록한다. 한 도식 안에서도 같은 색을 다른 뜻으로 쓰지 않는다.
- **색만으로 구분하지 않는다.** 채움 정도·윤곽 굵기·라벨(`L`/`R`, `d=2`)을 같이 써서 흑백으로 봐도 읽히게 한다.
- **평면·테두리 중심.** 그림자·그라데이션·글로우 없음, 둥근 모서리는 작게.
- **값은 코드로 계산.** 알고리즘 상태(포인터 위치, 거리, 큐, DP 값)는 손으로 적지 않고 풀이 로직을 도식 코드에서 실행해 얻는다.
- **작게, 핵심만.** 가장 작은 입력 하나를 추적한다. 변수는 독자가 따라가야 하는 것만 보여 준다.
- **한 프레임에 한 사건, 단계는 설명 순서로.** 코드의 실행 순서가 아니라 독자가 따라가기 쉬운 설명 순서(예: 0을 발견할 때마다 표시 → 표시가 끝나면 행·열 단위로 처리)로 나눈다. 너무 뭉치면 무엇이 바뀌었는지 안 보이고, 한 프레임에 정보를 다 얹으면 지저분하다. 중간 프레임의 값도 로직을 실행해 얻는다.
- **모든 도식이 같은 틀을 쓴다.** 폭·칸 크기·글자 크기·제목/단계/범례/캡션 위치와 전환 속도는 아래 `형태`·`형식`이 정하고, 숫자의 정본은 `diagram.py` 상수다. 도식마다 따로 정하지 않는다.

## 색 역할 (라이트 / 다크 토큰은 `diagram.py`)

| 역할           | 토큰         | 쓰임                                              |
| -------------- | ------------ | ------------------------------------------------- |
| 기본·처리 끝   | `ink`·`tint` | 윤곽·글자·옅은 채움, 이미 확정된 간선·노드        |
| 제외·미사용    | `dim`        | 범위 밖 칸, 아직 안 쓴 간선                       |
| 지금 보는 대상 | `blue`       | 현재 노드, 비교 중인 칸                           |
| 대기·후보      | `orange`     | 큐·스택에 든 것, 다음에 볼 후보                   |
| 확정·정답      | `green`      | 조건을 만족한 칸, 최종 답                         |
| 앞서 가는 쪽   | `red`        | 두 포인터 중 빠른 쪽(`fast`), `blue`와 짝         |
| 열 쪽 역할     | `purple`     | 행렬 구성에서 열 최솟값을 맡은 칸                 |
| 행 쪽 역할     | `yellow`     | 행렬 구성에서 행 최솟값을 맡은 칸                 |
| 지금 훑는 줄   | `ink` 윤곽선 | 지금 훑거나 처리하는 행·열(칸 색과 별개의 둘레선) |

위 역할 밖의 구분이 필요하면 `diagram.py` 팔레트에 `{색}`·`{색}_t`(옅은 채움)를 추가하고 이 표에 한 줄을 더한다. 색상은 색각 이상에서도 구분되는 Okabe-Ito 계열에서 고르고, 다크는 라이트보다 밝게 잡는다.

## 형태

- **캔버스 폭은 560으로 통일**한다(`CANVAS_W`). 높이는 내용만큼. 본문 폭에서 줄어도 숫자가 읽히도록 칸과 글자를 크게 둔다.
- **격자 칸 92×60, 간격 8, 모서리 반경 8**(`CELL_W`·`CELL_H`·`GAP`), 숫자는 모노 24(강조는 굵게). 칸 안 보조 라벨은 산세리프 15. 격자는 가로 가운데 정렬한다(`grid_x0`). 포인터는 칸 아래 삼각형+라벨.
- **노드 반경 24**, 윤곽 2.5, 안의 값은 모노 15. 간선 1.5(확정 간선은 굵게 3). 노드 아래 부가 값은 작은 회색. 그래프도 폭 560 안에 배치하고, 바깥쪽 라벨(`slow`/`fast`)이 캔버스 밖으로 잘리지 않는지 본다.
- 글꼴: 숫자·식은 모노스페이스, 한글 라벨은 산세리프(`MONO`/`SANS`). 크기는 제목 16(굵게)·단계 13(흐림)·캡션 15·범례 15로 고정한다(`FS_*`).
- **세로 구성은 항상 같은 순서**다: 제목(y 24) → 단계(GIF만, y 46) → 그림(y 68부터, `HEADER_H`) → 상태 줄(있을 때) → 범례(있을 때) → 캡션. 왼쪽 시작 x는 모두 16(`MARGIN`). `header`·`legend`·`caption` 헬퍼를 쓴다.
- **제목**은 도식이 다루는 입력(`n = 19`, `4×5 행렬`), **단계**는 `k / N단계`(첫 프레임은 `시작`)다.
- **범례**는 라벨을 직접 달지 못한 색만 설명한다. 칸·노드 옆에 라벨이 이미 있으면(`slow`/`fast`) 범례를 두지 않는다. 색 상자는 18×18, 가로로 늘어놓다 넘치면 2열.
- **캡션**은 GIF에서 필수다. 그 프레임에서 일어난 일을 한 문장으로 쓰고, 마지막 프레임은 결론을 굵은 `green`으로 쓴다. 정적 도식은 아래에 결론 줄을 둔다.

## 형식

- **정적 도식은 SVG**(투명 배경). **상태가 변하는 흐름은 GIF**(한 프레임이 한 단계, 프레임당 2초, 마지막 프레임 3.5초, 단색 배경, 2.5배 해상도, 무한 반복). 속도는 캡션을 읽을 시간을 주는 값이고 `diagram.py`의 `FRAME_MS`·`LAST_MS`가 정본이다. 정적 SVG에는 그 흐름에서 설명하려는 대표 프레임 하나를 쓴다.
- GIF는 크기가 커지니 프레임을 핵심 단계로 제한한다(대략 12프레임 이내).

## 다크 모드

라이트·다크 두 벌을 만들고 포스트에서 클래스로 고른다(Chirpy `_sass/themes`의 `.dark`·`.light` 숨김 규칙에 의존).

```
![설명](two-pointer-light.svg){: .light }
![설명](two-pointer-dark.svg){: .dark }
```

파일은 `assets/img/posts/{slug}/`에 두고 front matter `media_subpath`(스캐폴드가 넣는다)로 상대 경로를 쓴다. `diagram.py`의 `emit`이 `{이름}-light|dark.svg`·`.gif`를 한 번에 만든다. GIF만 쓰는 도식은 `static=False`로 호출해 SVG 파일을 만들지 않는다(임시 폴더를 거쳐 GIF만 옮기는 방식은 쓰지 않는다). 두 벌 모두 `alt`를 같게 쓴다.

## 생성 스크립트

**결과물과 같은 폴더에 `make_diagrams.py`로 둔다**(예: `assets/img/posts/leetcode-202/make_diagrams.py`). 도식과 만든 방법이 한곳에 있고, 포스트를 옮기거나 지울 때 같이 움직인다.

- 공용 모듈 `diagram.py`는 스크립트가 레포 루트 기준 경로로 불러온다.
- 위쪽 docstring에 입력 값 선택 이유, 출력 위치, 실행 방법을 적고, 인자 없이 돌리면 그 폴더의 GIF를 다시 만들게 한다. 도식이 여러 개면 한 스크립트에 함께 둔다.
- 수정하면 GIF를 다시 만들어 눈으로 확인한 뒤 같이 커밋해서, 이전 버전은 git 이력으로 남긴다.
- Python 포맷은 Prettier가 아니라 Ruff를 쓴다(VS Code의 `[python]` 설정이 저장 시 `ruff format`·fixAll·organizeImports를 돌린다). 명령줄로는 VS Code Ruff 확장에 번들된 `ruff format <파일>`로 같은 결과가 나온다.

## 만든 뒤 확인

틀린 도식은 없는 도식보다 나쁘다. 아래를 모두 하고, 못 한 항목은 보고에 적는다.

- **서식**: `emit`이 정적 SVG의 XML 오류와 렌더 실패를 막는다. 그 밖의 시각 문제(글자 잘림·겹침, 색 구분, 대비)는 라이트·다크 둘 다 처음·중간·마지막 프레임을 PNG로 내려 직접 본다(`rsvg-convert`로 래스터화한 뒤 Read로 연다).
- **값**: 도식의 상태는 풀이 로직을 도식 코드에서 실행해 얻고, 같은 입력으로 포스트의 코드 블록(Java·C++·Python 중 실행 가능한 것)을 실제로 돌려 최종 값이 같은지 대조한다. 스크립트 안에 `assert`로 남긴다.
- **설명**: 본문과 alt에 쓴 수치(입력, 반복 횟수, 만나는 값 등)는 손으로 옮기지 않고 스크립트 출력에서 가져와 한 글자씩 대조한다. 도식이 보여 주는 단계와 본문이 말하는 단계가 같은 순서인지, 색 역할이 본문 서술(예: "빠른 포인터")과 맞는지도 본다.
- **발행 전**: `lint_post.py`의 `이미지` 이슈가 0건이어야 한다(검사 항목은 `STYLE.md`, 위반이면 `publish`가 막는다).
- 로컬에서 `jekyll serve`로 `.light`/`.dark` 전환이 실제로 되는지 한 번 확인한다(사용자 몫).
