# sync — 포스트 코드 블록 재동기화

```
python3 <이 스킬의 base directory>/scripts/sync_code.py <포스트 .md 경로 | 폴더>
```

포스트 하나, 또는 폴더 아래 `.md` 전부(드래프트·발행분 무관). 에러가 있으면 종료 코드 1이다.

## 동작

1. front matter의 `date`/`slug`로 PS 레포 원본 폴더를 찾는다.
2. 폴더의 소스를 `ps`와 같은 `clean_code`로 정리해, 파일명 끝자리 숫자(접근법 번호)와 언어가 같은 `### 풀이`/`### 풀이 N` 구간의 코드 펜스를 교체한다. 범위는 `## N. 코드`/`## N. 쿼리` 섹션 안이고, 같은 구간·언어의 첫 펜스만 바꾼다.
3. 헤딩 접미어(`### 풀이 2: DP`)와 프로즈는 그대로 두고, 바뀐 게 있을 때만 파일을 다시 쓴다.

## 출력

포스트마다 `{상대경로} — {줄}`, 마지막에 총계 한 줄(`갱신함`·`변경 없음`·`확인 필요`·`에러` 개수).

- `{소스 파일명}: 갱신함` / `변경 없음`
- `에러: ...` — 그 포스트만 보고하고 계속한다.

아래 알림은 **고치지 않고 알리기만** 한다(구조를 바꾸는 판단은 사람 몫). 하나라도 있으면 그 포스트는 `확인 필요`로 센다.

- `{소스 파일명}: 포스트에 코드 블록이 없음` — PS 레포엔 있는데 그 접근법 구간에 그 언어 펜스가 없음(새 접근법·언어이거나 펜스를 구간 밖으로 옮김)
- `{언어} 코드(풀이 N): 포스트엔 있는데 PS 레포엔 없음` — 파일이 삭제되거나 이름이 바뀜
- `코드 섹션(...)을 못 찾음` — 포스트에 `## N. 코드`/`## N. 쿼리` 헤딩이 없음

## 규칙

- PS 레포 원본은 읽기만 한다.
- 결과를 보고할 때 "무시해도 될 듯" 같은 판단을 얹지 않는다.
- 발행분을 고쳤으면 `fix: [Platform] #번호 - ...` 손수정 커밋 대상이니 diff를 확인한 뒤 커밋한다.
