# ps — PS 포스트 스캐폴드 생성

**스코프**: 파일명 + front matter + 코드 섹션(완전 자동)까지. 아이디어·복잡도 셀 값은 사람이 채우거나(비어있으면 `review-post`가 대신 채움) 빈 값만 생성. 회고/참고는 스캐폴드에 아예 안 생성(아래 표 참고). 스켈레톤 설계 근거(구분선 소유권, 코드 라벨을 안 쓰는 이유, IAL 처리 등)는 `scripts/resolve_filename.py`/`scripts/clean_code.py` 주석에 있음 — 여기서 반복 안 함.

## 실행

무인자 배치가 기본 사용 패턴 — 사용자는 항상 이렇게 부른다("`ps` 돌려줘" = 개설일 이후 PS 레포 풀이 전체 스캐폴드). 인자 버전은 Claude가 특정 문제만 선별해 스캐폴드할 때(사용자가 "이 문제만" 지목), 또는 스켈레톤 구조 변경 후 재생성용.

**배치(인자 없이):**

```
python3 <이 스킬의 base directory>/scripts/resolve_filename.py
```

`PS_REPO` 전체를 스캔해서, 블로그 개설일(2026-08-17) 이후 존재하는 풀이 중 이 블로그에 아직 포스트/드래프트가 없는 것(front matter `slug` 기준) 전부를 스캐폴드로 생성함. 이미 있는 건 안 건드림(`--force` 자체를 안 받음). 폴더 하나가 실패해도 그 폴더만 에러로 보고하고 나머지는 계속 처리함. 같은 (플랫폼, 번호)가 서로 다른 day 폴더에 중복이면 스캐폴드를 만들지 않고 "충돌"로만 보고(사람이 직접 확인).

출력: `생성함: {경로}` / `에러({폴더}): {이유}` / `충돌(slug=...): ...` 목록 + 마지막에 총계 한 줄.

**특정 폴더 하나만:**

```
python3 <이 스킬의 base directory>/scripts/resolve_filename.py <PS레포 문제 폴더 절대경로> [--force]
```

예: `python3 .claude/skills/ps/scripts/resolve_filename.py /Users/mwzz6/Desktop/github/PS/2026-09/src/day_01/prms_42586`

Claude가 특정 문제만 선별 생성할 때, 또는 스켈레톤 구조가 바뀌어서 재생성할 때(`--force`) 씀. 성공하면 stdout엔 쓴 파일의 절대경로만 출력.

두 모드 다 `_drafts/{platform}/`(소문자, 예: `programmers`)에 씀 — **`_posts/`가 아님**(`publish`가 옮기기 전까진 초안, 사이트 비노출). 같은 이름 파일이 있으면 거부(사람이 채운 프로즈 보호). 실패 시 예외를 그대로 보고 — 임의 보정 금지.

로컬에서 초안 미리보기: `bundle exec jekyll serve --drafts` (`_config.yml`에 `show_drafts: true`를 넣는 방식은 쓰지 말 것 — 프로덕션 빌드에도 적용돼 초안이 실제 배포 사이트에 노출됨).

## 본문 구조

| 섹션                     | 채워지는 방식                                                                            |
| ------------------------ | ---------------------------------------------------------------------------------------- |
| 문제 링크(`prompt-info`) | 결정론적                                                                                 |
| 1. 아이디어              | 사람이 직접(비어있으면 `review-post`) — 프로즈 규칙은 `STYLE.md`                         |
| 2. 복잡도                | 행 구조는 결정론적, 셀 값·변수 설명은 사람/`review-post` — 표기는 `STYLE.md`             |
| 3. 코드                  | 완전 결정론적                                                                            |
| 회고 / 참고              | 스캐폴드에 안 생성 — 쓸 내용이 생겼을 때 사람이 `## 회고`/`## 참고`(번호 없음) 직접 추가 |

`1. 아이디어`·복잡도 변수 설명·코드 블록 설명의 어투·표기·금지 규칙은 전부 [`review-post/STYLE.md`](../review-post/STYLE.md)가 정본. 아래는 `ps` 스캐폴드가 만드는 **구조**만 다룬다.

### 복잡도 표

행 구조는 코드 섹션의 접근법 그룹과 1:1(같은 `group_by_approach`). "접근" 열은 `풀이:` 접두어 없이 이름만 — 접두어+이름 조합은 코드 섹션 헤딩에서만. 셀 값이 $O(1)$이 아니면 표 아래에 변수 설명 프로즈(포맷은 `STYLE.md`).

### 코드 섹션 · 다중 접근

- 같은 언어 파일이 폴더에 여러 개면(`Main.java`+`Main2.java`) 파일명 끝자리 숫자로 접근법을 나눠 그룹핑. 접근이 하나면 `### 풀이`, 둘 이상이면 첫 접근도 번호를 붙여 `### 풀이 1`/`### 풀이 2`. 헤딩엔 그 접근법에 존재하는 언어를 `[Java][C++]`로 표시.
- 접근법 이름(`풀이 2: DP` 등)은 스크립트가 안 채운다 — 사람이 헤딩을 직접 수정하거나, 비어 있으면 `review-post`가 채운다(규칙은 `STYLE.md`의 "다중 접근 — 접근 이름").
- **코드 블록을 자기 접근법 헤딩 구간 밖으로 옮기면 `sync`가 못 찾는다.**
- 헤딩 바로 아래(첫 코드 블록 위) 설명 = 그 접근법 전 언어 공통, 각 코드 블록 바로 아래 설명 = 그 언어 전용. 언어별 프로즈를 넣어도 `sync`는 fence만 정규식으로 교체하므로 안전하다(프로즈 규칙은 `STYLE.md`).

## front matter 필드

| 필드            | 채워지는 방식                                                                                                  |
| --------------- | -------------------------------------------------------------------------------------------------------------- |
| `title`         | 결정론적 — `"[{Platform}] #{번호} - {제목} [{언어1}][{언어2}]..."`                                             |
| `date`          | 결정론적 — 폴더 `day_{DD}`에서 뽑은 날짜만                                                                     |
| `categories`    | 결정론적 — `[PS, {platform}]`                                                                                  |
| `tags`          | 빈 배열 — 사람이 직접 작성                                                                                     |
| `slug`          | 결정론적 — `{platform}-{번호}` 소문자                                                                          |
| `media_subpath` | 결정론적 — `/assets/img/posts/{slug}/`                                                                         |
| `math`          | 결정론적 — 항상 `true` (복잡도 표가 `$O(1)$` 등 항상 `$...$` 수식을 쓰므로 수식 없는 포스트가 구조적으로 없음) |
| `mermaid`       | 기본 `false` — 본문에 다이어그램 있으면 직접 `true`로                                                          |

## 규칙

- 블로그 개설일(2026-08-17) 이전 풀이는 완전히 무시(스크립트가 자동 거부)
- 게시 선별 없음 — 스코프 안이면 전부 포스팅 대상
- 파일명 금지 문자(`/ : ? * " < > \ |`)는 육안 구별 어려운 유니코드로 자동 치환됨. **파일명에만 적용** — front matter의 `title`은 원문 그대로
- `description` front matter는 만들지 않는다 — PS 포스트에서 폐기된 필드(이유는 `review-post/STYLE.md` `## description`)
- **결과 보고 시 판단을 얹지 않음** — 필수 인자(문제 폴더 절대경로)가 없으면 평문으로 경로를 요청하고 기다린다. AskUserQuestion 같은 선택지 UI로 후보를 골라주지 말 것(참고용 목록을 텍스트로 곁들이는 것까진 OK). 스크립트 출력도 "괜찮아 보인다"/"무시해도 될 듯" 없이 사실만 전달 — 판단은 사람 몫
