# /sync — 코드블록 PS 레포 동기화

`_drafts/`의 기존 포스트가 참조하는 PS 레포 소스가 바뀌었을 때(버그 수정, 새 풀이 추가)
**코드블록만** 최신 상태로 맞춘다. 아이디어·복잡도 등 사용자가 쓴 산문은 절대 건드리지 않는다.

## 언제 쓰는가

- "PS 레포에서 코드 좀 고쳤는데 반영해줘" — 기존 풀이의 코드가 바뀐 경우
- "Solution2 추가했어" — 새 접근이 생겨서 포스트에 섹션이 통째로 필요한 경우
- `/review`나 대화 중 코드 버그를 발견해 PS 레포를 고친 직후

**대상은 `_drafts/`뿐이다.** 이미 발행된 `_posts/`는 범위 밖 — `/publish`·`fill`/`vars`와 같은
경계(발행본 수정은 전부 수동).

## 왜 코드블록을 직접 쓰는데도 규칙 위반이 아닌가

이 레포는 "PS 코드블록은 사용자 영역, Claude가 직접 고치지 않는다"는 원칙이 있다. `/sync`는
그 원칙과 충돌하지 않는다 — **PS 레포 소스에서 그대로 복사해온 텍스트를 드래프트에 다시
복사하는 것**이지, Claude가 새로 작성하거나 판단해서 고치는 게 아니다. 저작권은 여전히
100% 사용자 것이고(그 코드는 애초에 사용자가 PS 레포에 쓴 것), `/ps`가 처음 초안을 만들 때
하는 일과 본질적으로 같다 — 다만 새로 만드는 대신 이미 있는 걸 최신화할 뿐.

## 실행

### 1. 진단 (항상 먼저, 쓰기 없음)

```
python3 .claude/skills/sync/sync.py                # _drafts/ PS 포스트 전체 진단
python3 .claude/skills/sync/sync.py 154538          # 이 번호만
python3 .claude/skills/sync/sync.py 121 154538      # 여러 개
```

diff를 그대로 사용자에게 보여주고 **적용 여부를 확인받는다.** 스크립트가 잡는 4가지:

- **변경됨** — 기존 풀이의 코드가 PS 레포와 달라짐 (라인 diff로 표시)
- **새로 추가됨** — PS 레포에 draft가 모르는 접근(Solution2 등)이 생김. apply 시 `### N. 풀이`
  섹션 + 빈 복잡도 표가 새로 생긴다는 뜻을 같이 안내
- **언어 누락** (경고만, 자동 조치 없음) — PS 레포엔 있는 언어가 draft 코드블록엔 없음. 수동 추가 필요
- **소스 소실** (경고만, 자동 조치 없음) — draft엔 있는 접근인데 PS 레포에서 파일이 사라짐.
  자동 삭제하지 않으므로 사용자가 직접 판단

### 2. 적용 (확인 후에만)

```
python3 .claude/skills/sync/sync.py apply                # drift 있는 것 전부
python3 .claude/skills/sync/sync.py apply 154538          # 이 번호만
```

파일 쓰기는 전부 스크립트가 한다 — 코드블록 교체, 새 섹션·복잡도 빈 표 삽입까지 결정론적으로
처리한다. **직접 Edit으로 우회하지 말 것.**

## 접근(풀이) 매칭 방식

- draft의 `### N. 풀이` 순서 ↔ PS 레포 `Main`/`Main2`/... (또는 `Solution`/`Solution2`/...)
  파일 접미사 순서로 위치 매칭한다. **헤더 텍스트는 안 본다** — `### 1. bfs`, `### 2. dp`처럼
  사용자가 리네임해도 정상 동작한다.
- 접근 안의 언어는 코드펜스 언어 태그(` ```java `/` ```c++ `)로 매칭한다.
- **1개 → 2개+ 로 늘어나는 순간**(단일 포맷 → 번호 포맷 전환), 기존 접근 1의 `### 풀이`·복잡도
  표에도 자동으로 `1. ` 번호를 붙인다 — `/ps`가 처음부터 여러 접근으로 생성했을 때와 같은
  모양을 만들기 위해서다. 기존에 리네임한 라벨(`bfs` 등)이나 **이미 채워둔 복잡도 값**은
  그대로 보존한다.
- 새로 추가되는 접근은 기본 라벨 `N. 풀이`로 생성된다 — 리네임은 사용자 몫.

## 보고

- **진단**: 스크립트 출력(diff)을 그대로 전달. drift 없으면 "변경 없음"만 보고.
- **적용 전**: 무엇을 반영할지(변경 N건 / 신설 N건) 요약하고 확인받는다.
- **적용 후**: 스크립트의 적용 결과(어느 풀이·언어가 갱신/신설됐는지)를 그대로 전달.
- 언어 누락·소스 소실 경고가 있으면 자동 조치가 없다는 점과 함께 그대로 전달 — 사용자가
  PS 레포 쪽을 마저 정리하거나 draft를 손으로 맞출지 판단하게 한다.
