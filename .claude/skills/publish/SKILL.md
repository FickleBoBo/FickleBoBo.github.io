# publish — 결함 없는 PS 포스트 발행

```
python3 ${CLAUDE_SKILL_DIR}/scripts/publish.py <드래프트 .md 절대경로>
```

**한 번에 포스트 하나.** 사용자가 지목한 포스트를 `_drafts/{platform}/`에서 찾아(제목/번호로 매칭) 절대경로로 넘긴다. 여러 개면 포스트마다 한 번씩 실행한다(결함 있는 드래프트가 섞여 있어도 지목한 것만 발행). `_drafts/{platform}/`(platform ∈ `repo.PLATFORM_DIRS`) 밖의 경로는 거부된다. 막히거나 에러면 종료 코드 1이다.

## 발행을 막는 결함

발행 전에 아래를 전부 검사하고, 결함은 **첫 번째에서 멈추지 않고 모두** 모아 한 번에 보고한다. 하나라도 있으면 아무것도 안 건드린다.

- `tags`가 비어 있음 — 태그는 `tag` 스킬로 붙이는 단계라 빠진 채 발행되는 걸 막는다.
- `## 1. 아이디어` 본문(HTML 주석·구분선 제외)이 비어 있음.
- **린트 구조 위반** — `_shared/lint/`의 구조·태그 규칙(`lint(strict=True)`: 드래프트의 이름 없는 `### 풀이 N [언어]`도 위반). 규칙 목록은 `STYLE.md`와 `lint/` 도크스트링이 정본이다. 어투·맞춤법·수식 같은 **표기 이슈는 막지 않고** 발행 결과 뒤에 `표기 참고 N건`으로 알린다.
- **PS 소스 폴더를 못 찾음** — `date`/`slug`로 역산한 폴더가 없음.
- **코드 싱크 불일치** — 포스트 코드가 PS 레포 최신과 다르거나(`sync` 후 다시 발행), 포스트와 PS 소스의 대응이 안 맞음(PS에 있는 파일의 코드 블록이 포스트에 없음, 포스트 코드가 PS에 없음).
- `_posts/`에 같은 이름의 파일이 이미 있음.

회고/참고는 선택 섹션이라 비어 있어도 막지 않고 자동 삭제도 안 한다.

## 처리 순서

1. 결함 검사. 통과하지 못하면 블로그 레포는 그대로.
2. `_drafts/{platform}/{파일명}` → `_posts/{platform}/{파일명}` 이동.
3. 이동한 포스트와 (있으면) `assets/img/posts/{slug}/`를 블로그 레포에 커밋, PS 레포의 그 문제 폴더를 같은 메시지 `feat: {title}`로 커밋한다. 커밋 규약은 `CLAUDE.md`. **push는 사람이.**

이미 커밋된 상태(해당 경로에 변경 없음)면 그 레포 커밋은 건너뛰고 "이미 커밋된 상태"로 보고한다(에러 아님).

## 실패 처리

이동(2번) 뒤의 실패는 자동 롤백이 없다. 에러 메시지에 어디까지 진행됐는지 적혀 있다.

- 블로그 커밋 실패: 파일은 이미 `_posts/`에 있다. 사람이 `git add`/`commit`.
- PS 커밋 실패: 블로그는 이미 커밋된 상태. PS 레포만 직접 확인.

## 에디터 저장 레이스 (알려진 gotcha)

이동 직후 에디터에서 저장하면 옛 `_drafts/` 경로에 버퍼가 다시 flush돼 중복 파일이 생길 수 있다(실제 발생). 발행 전에 대상 파일을 에디터에서 닫는 게 예방책. 생겼다면 잔여 draft와 `_posts/` 현재본을 `diff -u`로 대조해 같으면 잔여 draft만 삭제(빈 `_drafts/{platform}/`도 `rmdir`). 커밋 자체는 정상이다.

## 출력

`발행함: {경로} — {블로그 커밋 여부}, {PS 커밋 여부}`(표기 이슈가 있으면 그 아래 `표기 참고 N건`) 또는 `에러({드래프트 경로}): 발행 막힘:` + 결함 목록. 결과 보고 시 판단을 얹지 않는다. PS 레포 소스 내용은 건드리지 않고 커밋만 한다.
