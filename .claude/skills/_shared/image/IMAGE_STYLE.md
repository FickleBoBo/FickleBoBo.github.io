# 포스트 이미지 스타일

PS 포스트의 도식 정본. 생성은 같은 폴더의 `diagram.py`(팔레트 토큰·그리기 헬퍼·SVG/GIF 출력)를 쓰고, 도식마다 `draw(c, frame, solid_bg)` 함수를 짠다. 샘플 구현: `assets/img/posts/leetcode-202/make_diagrams.py`(노드·간선·포인터 라벨, 사이클 탐색 GIF).

## 원칙

- **흑백이 기본, 구분이 필요하면 색을 더한다.** 먹색 윤곽, 옅은 회색 채움, 흐린 회색(제외·미사용)으로 먼저 구성하고, 그것만으로 독자가 상태를 못 가릴 때 색을 추가한다. 색 개수 상한은 없다.
- **한 역할에 한 색, 모든 도식에서 동일.** 새 역할이 생기면 색을 새로 고르되 아래 표에 등록한다. 한 도식 안에서도 같은 색을 다른 뜻으로 쓰지 않는다.
- **색만으로 구분하지 않는다.** 채움 정도·윤곽 굵기·라벨(`L`/`R`, `d=2`)을 같이 써서 흑백으로 봐도 읽히게 한다.
- **평면·테두리 중심.** 그림자·그라데이션·글로우 없음, 둥근 모서리는 작게.
- **값은 코드로 계산.** 알고리즘 상태(포인터 위치, 거리, 큐, DP 값)는 손으로 적지 않고 풀이 로직을 도식 코드에서 실행해 얻는다.
- **작게, 핵심만.** 가장 작은 입력 하나를 추적한다. 변수는 독자가 따라가야 하는 것만 보여 준다.

## 색 역할 (라이트 / 다크 토큰은 `diagram.py`)

| 역할           | 토큰         | 쓰임                                       |
| -------------- | ------------ | ------------------------------------------ |
| 기본·처리 끝   | `ink`·`tint` | 윤곽·글자·옅은 채움, 이미 확정된 간선·노드 |
| 제외·미사용    | `dim`        | 범위 밖 칸, 아직 안 쓴 간선                |
| 지금 보는 대상 | `blue`       | 현재 노드, 비교 중인 칸                    |
| 대기·후보      | `orange`     | 큐·스택에 든 것, 다음에 볼 후보            |
| 확정·정답      | `green`      | 조건을 만족한 칸, 최종 답                  |
| 앞서 가는 쪽   | `red`        | 두 포인터 중 빠른 쪽(`fast`), `blue`와 짝  |

위 역할 밖의 구분이 필요하면 `diagram.py` 팔레트에 `{색}`·`{색}_t`(옅은 채움)를 추가하고 이 표에 한 줄을 더한다. 색상은 색각 이상에서도 구분되는 Okabe-Ito 계열에서 고르고, 다크는 라이트보다 밝게 잡는다.

## 형태

- 배열 칸 64×52, 간격 8, 모서리 반경 8. 인덱스는 칸 아래 작은 회색 숫자. 포인터는 칸 아래 삼각형+라벨.
- 노드 반경 24, 윤곽 2.5. 간선 1.5(확정 간선은 굵게 3). 노드 아래 부가 값(`d=2`)은 작은 회색.
- 글꼴: 숫자·식은 모노스페이스, 한글 라벨은 산세리프(`diagram.py`의 `MONO`/`SANS`). 이미지 안 텍스트는 짧게 유지한다.
- 캔버스 폭 약 600~640. 본문 폭에서 줄어도 숫자가 읽히는 크기를 유지한다.

## 형식

- **정적 도식은 SVG**(투명 배경). **상태가 변하는 흐름은 GIF**(한 프레임이 한 단계, 1초 간격, 마지막 프레임 2.2초, 단색 배경, 2.5배 해상도, 무한 반복). 정적 SVG에는 그 흐름에서 설명하려는 대표 프레임 하나를 쓴다.
- GIF는 크기가 커지니 프레임을 핵심 단계로 제한한다(대략 10프레임 안팎).

## 다크 모드

라이트·다크 두 벌을 만들고 포스트에서 클래스로 고른다(Chirpy `_sass/themes`의 `.dark`·`.light` 숨김 규칙에 의존).

```
![설명](two-pointer-light.svg){: .light }
![설명](two-pointer-dark.svg){: .dark }
```

파일은 `assets/img/posts/{slug}/`에 두고 front matter `media_subpath`(스캐폴드가 넣는다)로 상대 경로를 쓴다. `diagram.py`의 `emit`이 `{이름}-light|dark.svg`·`.gif`를 한 번에 만든다. 두 벌 모두 `alt`를 같게 쓴다.

**생성 스크립트는 결과물과 같은 폴더에 `make_diagrams.py`로 둔다**(예: `assets/img/posts/leetcode-202/make_diagrams.py`). 도식과 만든 방법이 한곳에 있고, 포스트를 옮기거나 지울 때 같이 움직인다. 공용 모듈 `diagram.py`는 스크립트가 레포 루트 기준 경로로 불러온다. 스크립트는 입력 값 선택 이유, 출력 위치, 실행 방법을 위쪽 docstring에 적고, 인자 없이 돌리면 그 폴더의 GIF를 다시 만들게 한다. 도식이 여러 개면 한 스크립트에 함께 둔다. 수정하면 GIF를 다시 만들어 눈으로 확인한 뒤 같이 커밋해서, 이전 버전은 git 이력으로 남긴다. Python 포맷은 Prettier가 아니라 Ruff를 쓴다(VS Code의 `[python]` 설정이 저장 시 `ruff format`·fixAll·organizeImports를 돌린다). 명령줄로는 VS Code Ruff 확장에 번들된 `ruff format <파일>`로 같은 결과가 나온다.
