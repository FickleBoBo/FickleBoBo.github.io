# /ps — PS 포스트 뼈대 생성

`~/Desktop/GITHUB/Algorithm` 레포의 그날 풀이 소스코드를 읽어, 일관된 템플릿의 블로그 초안을
`_drafts/{플랫폼}/` 아래에 결정론적으로 생성한다. 제목은 각 플랫폼 API/페이지에서 자동 조회한다.

## 실행

번들된 스크립트를 그대로 실행하고 결과(생성된 파일 목록)를 보고한다. 스크립트가 모든 작업을
결정론적으로 처리하므로 임의로 내용을 지어내거나 템플릿을 바꾸지 말 것.

```
python3 .claude/skills/ps/generate.py $ARGUMENTS
```

- 인자: `[<YYYY-MM-DD|YYYY-MM>] [문제번호...] [--review]`
  - `/ps` — **인자 없음(기본·게으른 경로): 개설일(2026-07-24) 이후 Algorithm 레포 전체를
    훑어, 아직 초안/발행 포스트가 없는 풀이만 생성.** 대부분 이걸 쓴다.
  - `/ps 2026-07-24` — 그날 하루치 전부
  - `/ps 2026-07` — 그 달 전체 (2026-07-24 이후 날짜만)
  - `/ps 2026-07 120802 120803` — 해당 번호만
- **멱등**: `_drafts/`·`_posts/` 어디든 이미 있으면 SKIP. 매칭은 **날짜 무관 문제번호**
  기준이라(slug에 날짜가 없음) 제목을 나중에 고쳐도, 같은 문제를 다른 날 다시 풀어도
  중복 생성되지 않는다. 재실행해도 없는 것만 채운다.
- **TODO 제목 자동 복구**: 제목 조회가 실패해 `... {번호} TODO.md`로 남은 초안은
  SKIP 대상에서 제외된다. 다음 실행 때 제목을 다시 조회해 성공하면 **본문은 그대로 둔 채**
  front matter 제목·파일명(·`TODO` 링크)만 갱신한다. 즉 일시적 네트워크 실패는
  `/ps` 재실행만으로 복구된다. 다시 실패하면 그대로 두고 알린다.
- 생성 섹션: **아이디어 / 복잡도 / 코드**. 리뷰 섹션은 기본 제외 —
  사용자가 "리뷰 넣어서" 등으로 요청하면 `--review`를 붙여 실행한다.
- 풀이는 **접근(알고리즘) 단위로 그룹화**된다(`Main`/`Main2`=서로 다른 접근,
  한 접근 안의 여러 언어는 같은 `풀이` 헤더 아래). 복잡도는 **접근당 표 하나**.
  접근이 2개+면 복잡도·코드 둘 다 `풀이 1`, `풀이 2`…로 나뉘고 번호가 서로 대응한다.
- **이미 생성된 초안에 리뷰를 추가**해달라는 요청이면, 스크립트는 기존 파일을
  SKIP하므로 재실행하지 말고 해당 `.md` 파일을 직접 편집해 코드 섹션 뒤에
  `## N. 리뷰`(마지막 섹션 번호) → `없음.` → `---`을 붙인다(`--review` 출력과 동일하게).
- 지원 플랫폼: 프로그래머스(prms) · 리트코드(leet) · 코드포스(cofo)
- 2026-07-24 이전 날짜는 스크립트가 자동으로 건너뛴다.
- 백준(boj)은 온라인 저지 종료(2026-04-28)로 제외. 재오픈 시 다시 추가한다.

## 제목 조회 참고

- 프로그래머스: 각 사이트에서 정상 조회된다.
- 리트코드: `questionFrontendId`(사용자에게 보이는 번호)로 조회. 검색이 안 잡히면 `TODO`.
- 코드포스: `problemset.problems`(아카이브 전체)로 조회. 아카이브에 아직 없는 최신 대회·gym
  문제만 `contest.standings`로 폴백한다. 둘 다 실패하면 `TODO`.

## 보고

스크립트 출력에서 아래를 사용자에게 요약한다.

- 생성된 초안 파일 경로 (`_drafts/{플랫폼}/...`)
- `Retitled TODO -> ...` 항목 (이전 실행의 조회 실패가 복구된 것)
- 제목 조회 실패로 `TODO`가 남은 항목 (있으면 수동 입력 필요)
- 코드 파일을 못 찾아 건너뛴 문제 (있으면)

제목이 `TODO`로 남은 경우에만 해당 문제 페이지를 확인해 제목/링크를 채워 넣는 것을 제안한다.
그 외에는 스크립트 결과를 그대로 신뢰한다.
