# publish — 완료된 PS 포스트 발행

## 실행

```
python3 <이 스킬의 base directory>/scripts/publish.py <드래프트 .md 절대경로>
```

**한 번에 포스트 하나.** 사용자가 지목한 포스트를 `_drafts/{platform}/`에서 찾아(제목/번호로 매칭) 절대경로로 넘긴다. 여러 개면 포스트마다 한 번씩 실행한다(전체 배치 모드는 없음 — 미완성 드래프트가 섞여 있어도 지목한 것만 발행). 허용 경로는 `_drafts/{platform}/` 아래(platform ∈ `blog_common.PLATFORM_DIRS`)뿐이라 PS 아닌 드래프트 폴더(`_drafts/contest/` 등)는 거부된다.

## 완료 판정

순수 내용 검사 — 사람이 `ready` 플래그를 켜지 않는다. 하나라도 안 맞으면 아무것도 안 건드리고 사유와 함께 에러(종료 코드 1)로 끝난다:

- front matter `categories: [PS, {platform}]`의 플랫폼이 드래프트가 놓인 폴더와 같음 — 발행은 폴더명 그대로 `_posts/{폴더}/`로 옮기므로, 다른 플랫폼 폴더에 모아 둔 드래프트가 엉뚱한 곳에 발행되는 걸 막는다
- `tags`가 비어 있지 않음 — 태그는 `review-code` 후 붙이는 단계라 빠진 채 발행되는 걸 막는다(어휘·순서 검증은 `review-post/scripts/lint_post.py`의 몫)
- `## 1. 아이디어` 본문(HTML 주석·구분선 제외)이 비어 있지 않음
- `## 2. 복잡도` 표의 모든 행에서 시간/공간 셀이 둘 다 채워짐

회고/참고는 선택 섹션이라 비어 있어도 발행을 막지 않고 자동 삭제도 안 한다.

**SQL 전용 포스트 예외**: `ps`가 SQL 전용 포스트엔 `## 2. 복잡도`를 안 만들므로(`ps/SKILL.md` 참고) title의 언어 브래킷이 `[MySQL]` 하나뿐이면 복잡도 검사를 건너뛴다. 헤딩 부재로 판정하지 않는 이유: 일반 포스트에서 그 헤딩이 실수로 지워져도 조용히 통과해 fail-closed가 깨지기 때문.

## 처리 순서

1. front matter의 `date`/`slug`로 PS 레포 원본 폴더를 역산 + 존재 검증(`_shared`의 `resolve_source_folder`). 실패하면 블로그 레포는 아직 아무것도 안 건드린 상태.
2. `_posts/`에 같은 이름 파일이 있으면 마찬가지로 아무것도 안 건드리고 에러.
3. `_drafts/{platform}/{파일명}` → `_posts/{platform}/{파일명}`로 이동.
4. 이동한 포스트 + (있으면) `assets/img/posts/{slug}/`를 블로그 레포에 커밋. 메시지 `feat: {title}` (예: `feat: [Programmers] #154538 - 숫자 변환하기 [Java][C++]`).
5. PS 레포의 그 문제 폴더를 같은 메시지로 커밋.
6. 두 커밋 다 `Co-Authored-By: Claude <noreply@anthropic.com>` 트레일러(스크립트가 커밋하므로 모델명 없음 — `CLAUDE.md` "트레일러 모델명 규칙").
7. **push는 안 함.** 로컬 커밋까지만, 배포로 이어지는 push는 사람이.

이미 커밋된 상태(해당 경로에 변경사항 없음)면 그 레포 쪽 커밋은 건너뛰고 "이미 커밋된 상태"로 보고 — 에러 아님.

## 실패 처리

- 완료 판정·1·2번 실패 → 아무것도 안 건드림.
- 4번(블로그 커밋) 실패 → 파일은 이미 `_posts/`로 이동된 상태. 자동 롤백 없음, 사람이 `git add`/`commit`.
- 5번(PS 커밋) 실패 → 블로그는 이미 커밋된 상태. PS 레포만 직접 확인.

에러 메시지에 어디까지 진행됐는지 적혀 있다.

## 에디터 저장 레이스 (알려진 gotcha)

이동 직후 에디터에서 저장하면 옛 `_drafts/` 경로에 버퍼가 다시 flush돼 중복 파일이 생길 수 있다(실제 발생). 발행 전에 대상 파일을 에디터에서 닫는 게 예방책. 생겼다면 잔여 draft·`_posts/` 현재본을 `diff -u`/md5로 대조해 동일하면 잔여 draft만 삭제(빈 `_drafts/{platform}/`도 `rmdir`). 커밋 자체는 정상이다(`git diff HEAD -- <파일>`이 비어 있으면 확인).

## 출력

한 줄:

- `발행함: {경로} — {블로그 커밋 여부}, {PS 커밋 여부}` (`블로그 커밋함`/`블로그 이미 커밋된 상태`, `PS 레포 커밋함`/`PS 레포 이미 커밋된 상태`)
- `에러({드래프트 경로}): {메시지}` — 미완료 사유(`미완료 — ...`)이거나 위 실패 케이스

## 규칙

- PS 레포 원본 소스 내용은 건드리지 않음(커밋만) — 코드 정리는 `ps`/`sync`의 몫.
- 결과 보고 시 판단을 얹지 않고 사실만 전달.
